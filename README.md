# mail-agent — mini-ассистент «Коля»

## Сборка

```
./mvnw -q package
```

Собирает fat-jar `target/mail-agent.jar` (`Main-Class: com.mailagent.Main`).

## Тесты

```
./mvnw test
```

Проходит на машине без Outlook (jacob исключён из test-classpath).

## Запуск

Требует Windows + Outlook и API-ключ LLM в переменной окружения, заданной в конфиге (`llm.apiKeyEnv`, по умолчанию `ANTHROPIC_API_KEY`).

```
set ANTHROPIC_API_KEY=sk-ant-...
java -jar target/mail-agent.jar config.yaml
```

Аргумент — путь к конфигу (по умолчанию `config.yaml` в текущей директории). Останов — `Ctrl+C`/`SIGTERM`.

### Конфиг (`config.yaml`)

```yaml
llm:
  endpoint: https://api.anthropic.com/v1/messages
  model: claude-sonnet-5
  apiKeyEnv: ANTHROPIC_API_KEY   # имя env-переменной с ключом, не сам ключ
  timeoutMs: 30000
agent:
  maxSteps: 6
store:
  path: ./data                  # reminders.json, seen.txt
mail:
  pollSeconds: 30
  profile: Outlook
  folder: Inbox
audit:
  path: ./data/audit.log
  hmacKeyEnv: AUDIT_HMAC_KEY     # опционально; без него — SHA-256 chain + WARN
```

## как работал с ии

писал все через Claude Code, одна сессия, с пустого репозитория.

### стратегия промптов

сначала попросил не код а план - получился PLAN.md: архитектура, контракты (MailChannel/LlmClient/Tool), схема идемпотентности/аудита/логов, и пошаговый список задач. дальше шел строго по tdd на каждый пункт: сперва падающий тест отдельным коммитом (test: red), потом реализация и зеленый прогон отдельным коммитом (feat: green). в git log это видно как пары коммитов почти на каждом шаге.

единственное исключение - jacob (OutlookMailChannel) и кусок Main который его собирает. юнит-тест тут в принципе невозможен, раз jacob целиком исключен из test-classpath по заданию. эти куски одним коммитом, без теста, честно помечено почему, а проверялось руками - реальной сборкой и запуском jar.

### что проверял у модели

формат tool calling у anthropic api (content-блоки, tool_use/tool_result, stop_reason) - перепроверил через веб-поиск, не стал полагаться на память модели, мало ли устарело.

реальные методы jacob (ComThread, ActiveXComponent, Dispatch.call/get/put, GetItemFromID для реплая) - тоже не поверил на слово. раздекомпилировал javap-ом настоящий class-файл из зависимости в локальном репозитории, посмотрел что там реально есть, а не что модель предположила по обучению.

### что отклонил

когда все собралось и тесты позеленели, не остановился на этом - собрал жирный jar и реально запустил. он упал: у зависимости xyz.cofe:jacob:1.20 с maven central физически нет файла META-INF/JacobVersion.properties, без которого jacob падает еще до всякого com-вызова. то есть упало бы и на реальной машине с outlook на защите, не только у меня локально. добавил недостающий файл руками, пересобрал, убедился что падение сдвинулось туда куда должно (UnsatisfiedLinkError на нативную dll, потому что тут нет винды с outlook) - и только после этого закоммитил.

еще не согласился со стандартным скиллом security-review в дефолтном виде - он весь заточен под дифф фичабранч-vs-main, а у меня по процессу все коммиты сразу в main, так что диффа не было вообще, пусто. вместо того чтобы принять пустой результат как "нет находок", прогнал ревью руками по тем же категориям (секреты, пдн в логах, инъекции в tool-аргументах) - находок в итоге не было, но убедился сам, а не поверил что пустой дифф значит все чисто.
